# 桌面录制模块 (Desktop Recording Architecture)

本目录实现 Windows 桌面及游戏窗口的原生音视频录制。ADB 模式录制仍由 `features/adb_mode` 处理。

---

## 1. 架构概览与数据流动

录制系统采用 **独立后台控制线程 + 三路独立工作线程流水线** 的解耦模型，保证媒体编码与文件 I/O 绝不阻塞 UI 线程。

### 数据流向示意图

```text
WGC(2帧) → 取最新/裁剪 → latest(1张) → 转换 → 4槽NV12/P010池 → 视频MFT ┐
                                                                     ├→ 压缩包交错 → 分片MP4 → Hybrid索引
WASAPI → 有界来源PCM → 连续采样时钟/缺口静音 → AAC MFT ─────────────────┘
```

### 核心处理逻辑

1. **视频流 (`video.cpp`)**：
   * WGC（Windows.Graphics.Capture）帧池固定 2 张，帧到达时唤醒视频线程，裁剪并缓存最新画面；
   * 按目标 FPS 提交画面，WGC 暂无新帧时沿用缓存画面，使用新的时间戳；
   * Direct3D 11 Compute Shader 将缓存画面（SDR BGRA 或 HDR scRGB）转换为 BT.709 limited NV12 或 BT.2020/PQ P010；
   * 从固定 4 槽位有界池中租借目标纹理，包装为 `IMFTrackedSample` 提交给异步硬件/同步软件 MFT 编码；
   * 底层 MFT 释放样本时通过 COM 回调自动归还槽位；从 MFT 拉取压缩数据包后投递至 Mux 待写队列。

2. **音频流 (`audio.cpp`)**：
   * WASAPI Loopback 捕获系统声音或指定游戏进程声音（固定协商 48kHz 16-bit 双声道）；
   * 来源采样进入最大 1 秒的有界 PCM 缓冲区，按采样序号平滑抖动，断流重连时重新树立时间锚点；
   * 编码线程按 10ms（480 采样点）固定步进向前推进，缺声区间自动填补静音，送入同步 AAC MFT 编码；
   * 拉取 AAC 压缩数据包后投递至 Mux 待写队列。

3. **封装流 (`mux.cpp`)**：
   * 纯压缩包直通写入：配置分片 MP4（`IMFSinkWriter`），显式禁用内部格式转换器，拒绝插入任何额外 MFT；
   * 压缩包队列上限 256MiB，达到 64MiB 并持续 1 秒时每段提醒一次；超过内存上限或写入失败时停止；
   * 录制停止并 Finalize 后，调用 `utils::media::hybrid_mp4` 原位重构文件头部索引，兼顾防掉电断流与播放秒开。

4. **控制流 (`usecase.cpp` / `control_thread`)**：
   * 独立后台控制线程串行消化 UI 或热键动作（`UserStart`、`UserStop`、`RestartAfterResize`、`ShutdownStop` 等）；
   * 全程不阻塞 UI 渲染循环。

## 2. 核心领域不变式 (Domain Invariants)

以下为保证录制稳定性与数据完整性不可违背的铁律：

### 视频与图像
* **4 槽有界池，绝不扩容**：编码输入池固定为 4 槽位，杜绝过载时内存无限膨胀。槽位归还完全以底层 `IMFTrackedSample` 释放回调为准，而非编码器输出时刻。
* **目标 FPS 不是欠帧队列**：暂时无输入额度或空闲纹理时等待，时间格过期后才跳过；恢复后提交当前画面，不补发历史帧。
* **零 B 帧重排序**：流水线要求输出 PTS 必须严格等于 DTS 且单调递增。一旦检测到时间戳回退或重排序立刻报错中止。
* **后 PTS 定前 Duration**：保留一个待发压缩包，以上一帧与当前帧的 PTS 之差作为真实持续时间。录制停止时，将末帧 duration 精确延伸至绝对截止点。

### 音频与时钟
* **来源可断，录像时钟不可缩**：声音来源发生断流、重连或设备切换时，缺失的时间段一律填充全零静音，录像总时长绝对不能被扣减或丢弃。
* **时间戳平滑**：WASAPI 时间戳与理论连续时钟偏差小于 70ms 时自动平滑对齐；超出阈值或出现不连续标记时重新树立 QPC 时间基准锚点。
* **来源缓冲有界**：来源 PCM 缓冲上限为 1 秒。严重超载时清空重置，绝不阻塞 WASAPI 硬件采集线程。

### 停止与收尾
* **绝对 QPC 截止点锁定**：停止请求提交瞬间立即锁定绝对 QPC 截止时间戳（`stop_qpc_100ns`）。关闭设备耗时与控制排队耗时绝不计入录像时长，各工作线程按截止点收尾，不追补视频帧。
* **误触短段丢弃**：编码产生的视频帧数不超过阈值（3 帧）时视为误触短录，自动删除文件；异常故障产生的有效分片一律保留入库。
* **生命周期原子性**：单段录制由 `RecordingSession` 独占拥有。所有工作线程（video、audio、mux）全部退出前，绝对禁止销毁会话或归还 1ms 定时器精度。

## 3. 代码组织与职责边界

| 文件 | 核心职责 |
| :--- | :--- |
| `usecase.cpp` | UI/热键 Toggle 响应、尺寸变更自动切段重启、通知分发、画廊入库收尾 |
| `recording.cpp` | 单段会话生命周期（`start`/`stop`）、三线程起止屏障、控制动作优先级仲裁 |
| `video.cpp` | WGC 画面消费、帧节拍步进、D3D11 格式转换、4 槽池借还、异步 MFT 编码与 Drain |
| `audio.cpp` | WASAPI 采样接收、时间戳平滑、静音填补、10ms 步进、AAC 编码与 Drain |
| `mux.cpp` | 256MiB 有界双流交错、SinkWriter 分片写入、Hybrid MP4 原位整理 |
| `time.cpp` | 统一 100ns QPC 时钟换算、总序号取整与负采样点位置计算 |
| `state.hpp` | `RecordingSession` 与 `RecordingState` 结构体集中管理 |
| `types.hpp` | 编码格式、控制动作、配置项等纯 POD 枚举与数据结构 |

> 注：底层无状态媒体基础设施位于 `src/utils/media/`（`mft`、`video_convert`、`sink_writer`），不依赖业务层的 `core::AppState`。
